# Дунавска китка — подготовка за Cloudflare

Това е подготвена и локално проверена миграция. Не е публикувана и не е свързана с живия сайт. Данните и файловете още не са прехвърлени. Работещият GitHub Pages сайт продължава да използва стария сървър.

## Вход и адреси

- `dunavska-kitka-admin.<поддомейн>.workers.dev/admin` — защитен панел.
- `dunavska-kitka-api.<поддомейн>.workers.dev` — публични данни, формуляри и медия.
- Администратори: двата вече одобрени имейла, зададени в `CF_ADMIN_EMAILS`.
- Вход чрез Cloudflare Access и еднократен код по имейл. Не се използват ChatGPT профили или споделена парола.
- ЦЕЛИЯТ хост на админ Worker трябва да бъде защитен с Access, не само `/admin`. Backend-ът проверява подписа, издателя, приложението, срока на токена и разрешения имейл.
- Публичният Worker премахва идентификационните заглавки и cookies, разрешава само публични операции и не допуска качване или редактиране.

## Необходими действия преди публикуване

1. Собственикът създава Cloudflare акаунт и приема условията лично. Никога не изпращайте парола, еднократен код или API token в чата.
2. Създайте D1 база `dunavska-kitka` и R2 bucket `dunavska-kitka-media` в този акаунт. R2 може да изисква активиране с платежен метод; платени настройки не трябва да се включват без отделно решение на собственика.
3. В Cloudflare Zero Trust добавете One-time PIN като вход и Access приложение за целия бъдещ hostname на админ Worker. Allow policy: Emails, точно двата одобрени имейла. Не добавяйте Allow Everyone или само Login method без имейл ограничение.
4. Вземете Account ID, Database ID, Access Team Domain (`име.cloudflareaccess.com`) и Access Application Audience (AUD). Това са настройки, не пароли.
5. Удостоверете Wrangler в собствения си терминал: `pnpm exec wrangler login`. Входът и разрешенията се потвърждават от собственика.

## Проверка и публикация

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
```

Задайте променливите в терминала си (не ги записвайте в публично хранилище):

- `CF_ACCOUNT_ID`
- `CF_DATABASE_ID`
- `CF_ACCESS_TEAM_DOMAIN`
- `CF_ACCESS_AUD`
- `CF_ADMIN_EMAILS` (двата разрешени имейла, разделени със запетая)

```sh
pnpm cf:configure
pnpm exec wrangler d1 execute dunavska-kitka --remote --file drizzle/0000_blue_katie_power.sql
pnpm exec wrangler d1 execute dunavska-kitka --remote --file drizzle/0001_easy_kat_farrell.sql
pnpm cf:deploy
pnpm cf:deploy-api
```

Името на SQL файла проверете в папката drizzle; използвайте реалния `0000*.sql`, ако то е различно. Приложете и останалите съществуващи миграции по ред. Access трябва да е настроен за целия админ hostname, преди реални данни да се заредят. Не допускайте публичен достъп до админ Worker.

## Прехвърляне на данните

Направете пълен актуален export на двете таблици от стария сървър: `records` и `votes`. Форматът трябва да е JSON с масиви `records` и `votes`, с оригиналните полета и без съкращаване. Не използвайте снимка на таблицата или съкратен текст. Export-ът съдържа лични данни; запазете го локално и не го качвайте в GitHub.

```sh
node scripts/import-data.mjs full-export.json import.sql
pnpm exec wrangler d1 execute dunavska-kitka --remote --file import.sql
```

Прехвърлете и всички качени R2 обекти, запазвайки оригиналните ключове и Content-Type. Само прехвърляне на таблиците няма да прехвърли снимките и видеата. Старият сървър остава наличен за връщане назад.

## Смяна на адреса в GitHub Pages — последна стъпка

Само след публикуване и прехвърляне:

1. Проверете входа на двамата администратори и отказа за трети имейл.
2. Проверете новия публичен API, записване в група, гласуване, качване на снимка/видео и управлението на репетиции.
3. Сравнете броя записи, резултатите на анкетите и всички медийни URL адреси.
4. Обновете `VITE_API_ORIGIN` към действителния нов публичен API, компилирайте публичния проект и публикувайте в GitHub Pages.
5. Старите източници могат да се изключат едва след успешна проверка и наличен архив.

## Локална проверка

Успешна компилация на Worker, тестове за подписани администраторски токени, неправилен подпис, изтекъл токен, чуждо приложение/издател, непознат имейл и опит за редакция през публичния API. Реално публикуване и проверка на жив вход още не са изпълнени.
