# Дунавска китка — GitHub Pages + Supabase

ПОДГОТВЕНО ЗА ПРЕГЛЕД. Няма публикувана Supabase версия. Работещият сайт
не трябва да се превключва преди прехвърляне и проверка на данните.

Сайтът и админ панелът се компилират като едно статично Vite приложение.
Админът е достъпен на `/#/admin`; `public/404.html` пренасочва и директния
адрес `/dunavska-kitka/admin` към него. Няма Cloudflare runtime и ChatGPT вход.

## Настройване

1. Създайте Supabase проект Free и запазете Project URL и publishable/anon key.
   Никога не поставяйте service_role/secret key във Vite или GitHub Pages.
2. В SQL Editor изпълнете `supabase/schema.sql`. Проверете дали таблиците са
   с включен Row Level Security; SQL файлът създава политиките.
3. Authentication → Providers → Email: включете потвърждение на имейл.
   Първият разрешен имейл се добавя само в личния SQL Editor:
   `insert into public.club_admin_emails(email) values (lower('ВАШИЯТ_ИМЕЙЛ'));`
   После администраторът се регистрира със собствена парола и потвърждава
   по имейл. Останалите администратори се добавят от админ панела.
4. Настройте `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` при Vite build.
   Те се вграждат в браузърния код и затова се използва само публичният ключ.
5. Качете пълния export на `records` и `votes` от стария сървър в частен файл;
   `node scripts/convert-export.mjs export.json` създава `import.sql`.
   Изпълнете SQL в Supabase SQL Editor. Не качвайте export или SQL с лични
   данни в GitHub. Изтеглете старите медии и качете отново в Storage;
   заменете старите `/api/media/...` адреси с новите HTTPS адреси.
6. Проверете двете администраторски регистрации, групи, снимки, формуляр
   за записване, анкета и администраторските резултати. След това публикувайте
   `dist/` в GitHub Pages, без да променяте потребителския адрес.

`pnpm install --frozen-lockfile` и `npm run build` изграждат сайта.
Supabase Storage Free допуска файл до 50 MB. Клипове над този лимит могат
да бъдат добавяни с външен HTTPS линк. Публичен видео файл не може надеждно
да бъде предпазен от запис на екрана или изтегляне.

Съдържанието се чете публично; записванията и резултатите се четат само от
администратори чрез RLS. Публичните форми извикват проверяващи SQL функции.
